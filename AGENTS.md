# Сайт Ольги Борзенковой — borzenkova.ru

Инструкция для ИИ-агента (Codex, Claude), который правит этот сайт по просьбе
владелицы. Она не программист: пишет задачи обычными словами («добавь статью»,
«поменяй цену», «замени фото»).

## Как с ней общаться

- По-русски, без терминов. Не «закоммитил в main», а «изменение опубликовано,
  через пару минут будет на сайте».
- В конце каждой задачи — коротко, что именно поменялось на сайте, человеческими
  словами: какой блок, какой был текст, какой стал.
- Если просьба неоднозначная («сделай покрасивее») — переспроси, прежде чем
  переделывать вёрстку.

## Как изменения попадают на сайт

Всё, что оказывается в ветке `main` на GitHub, **автоматически публикуется** на
borzenkova.ru примерно за 1–2 минуты (GitHub Actions: сборка → проверка →
выкладка). Отдельной кнопки «опубликовать» нет: `git push` в `main` — это и есть
публикация.

Порядок работы над каждой задачей:

1. **В начале — `git pull`**, чтобы работать с последней версией сайта.
2. Внести правки.
3. **`npm run check`** — в конце должно быть `✓ сборка в порядке`. Это та же
   проверка, что на GitHub; не прошла здесь — не пройдёт и там.
4. Если она хочет посмотреть до публикации — `npm run dev` и ссылка
   http://localhost:5173 (остановить сервер после просмотра).
5. `git commit` с понятным описанием по-русски («Новая статья про …», «Цена
   „Карты решения“ 5 900 ₽») и `git push`.
6. Сказать ей, что опубликовано и через пару минут будет на сайте.

Если сборка или проверка на GitHub упадёт — ничего не опубликуется, на сайте
останется прошлая версия. Сайт от этого не ломается.

Если `git push` отклонён (значит, `main` на GitHub успел измениться) —
`git pull --rebase`, снова `npm run check`, снова `git push`. **Никогда не
`--force`**: он всё равно запрещён на GitHub, а попытка только запутает.

### Разрешения в приложении Codex

Приложение по умолчанию спрашивает разрешение на команды, которым нужна сеть
(`npm ci`, `git pull`, `git push`) или запись в `.git` (`git commit`). Перед
таким запросом скажи ей простыми словами, что сейчас произойдёт: «скачаю
последнюю версию сайта», «сохраню изменения», «опубликую на сайт».

### Подпись коммитов

Репозиторий публичный — история видна всем. Коммиты подписываются адресом
`...@users.noreply.github.com`, а не личной почтой. Если
`git config user.email` в этом репозитории не заканчивается на
`@users.noreply.github.com` — не коммить, а сначала поправь (для неё:
`git config user.email "332468384+osborzenkova@users.noreply.github.com"`).

Незаконченную работу не пушь — в `main` всё сразу становится публичным.
Не клади в репозиторий ничего личного (данные клиентов, телефоны, пароли).

## Где что лежит

Почти весь контент — в одном файле **`src/main.tsx`**:

| Что на сайте | Где в `src/main.tsx` |
|---|---|
| Пять карточек «С какой ситуацией вы пришли?» | массив `segments` |
| Статьи блога | массив `posts` |
| Форматы работы и цены | массив `products` |
| Меню, первый экран, «Об Ольге», «Как это работает», контакты, подвал | функции `Header` и `Home` (текст прямо в разметке) |
| Страница статьи | функция `Article` |

- Стили (цвета, шрифты, отступы) — `src/styles.css`. Цвета — переменные в
  `:root` в начале файла.
- Картинки — `public/assets/`. В коде подключаются как `asset('имя-файла.png')`.
- Заголовок вкладки и описание для поисковиков — `index.html`
  (`<title>` и `<meta name="description">`).

### Как добавить статью в блог

Добавь объект в массив `posts` (новые — в начало массива, чтобы были первыми):

```ts
{slug:'latinica-cherez-defis',tag:'РЕШЕНИЯ',title:'Заголовок статьи',lead:'Подзаголовок в одну-две фразы.',read:'5 минут',body:['Первый абзац.','Второй абзац.','Третий абзац.']},
```

- `slug` — адрес статьи: латиница, цифры и дефисы, без пробелов, уникальный.
  Статья откроется по `https://borzenkova.ru/#/blog/<slug>`.
- `tag` — рубрика заглавными (как у существующих: РЕШЕНИЯ, ПАРТНЁРСТВО, МЕТОД).
- `read` — примерное время чтения (~1 минута на 1000 знаков).
- `body` — каждый абзац отдельной строкой в кавычках. Кавычки внутри текста —
  «ёлочки», не прямые `'`, иначе сломается код.

### Картинки

- Формат JPG или WebP для фото (PNG — только для графики с прозрачностью).
- Ширина не больше 2400 px, вес желательно до 1 МБ. **Больше 5 МБ проверка не
  пропустит** — сожми перед добавлением.
- Имя файла — латиницей, без пробелов: `olga-conference-2026.jpg`.
- Заменить фото, не меняя код, — положи новый файл под тем же именем.

## Чего не делать

- **Не трогай** `.github/`, `scripts/verify-dist.sh`, `vite.config.ts`,
  `package.json`, `package-lock.json`, `tsconfig.json` — это механика сборки и
  публикации. Если без правки там задачу не решить — остановись и скажи ей, что
  нужен Никита.
- Не добавляй новые npm-зависимости, аналитику, счётчики, виджеты, чаты.
- **Не добавляй формы, собирающие персональные данные** (имя, телефон, почта).
  Это юридические обязательства по 152-ФЗ: политика, согласие, уведомление
  Роскомнадзора. Все контакты ведут в Telegram — так и оставь.
- У тебя нет доступа к серверу, и он не нужен: не пытайся заходить по ssh, не
  проси пароли. Публикация — только через `main`.
- Не переписывай историю git (`push --force`, `reset` опубликованных коммитов).

## Если что-то пошло не так

«Верни как было» → найди коммит с неудачным изменением и сделай `git revert`
этого коммита, затем опубликуй как обычно. Не удаляй коммиты — откат тоже
должен остаться в истории.
